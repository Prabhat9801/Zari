# ZARI — FRONTEND PRODUCT BUILD SPECIFICATION

You are building the complete production-quality frontend for **Zari**, a premium Indian custom-fashion marketplace.

Zari's tagline is:

**"From Inspiration to Stitching."**

## PRODUCT DEFINITION

Zari is NOT an "AI fashion app".

Zari is a two-sided marketplace where customers can:

1. Upload a fashion inspiration image or describe an outfit.
2. Generate manufacturable outfit concepts.
3. Edit the design conversationally.
4. See transparent itemised cost estimates.
5. Optimize the design to fit a target budget.
6. Request quotes from verified designers.
7. Compare designers using an AI Quality Score.
8. Place an order through escrow.
9. Track production milestones.
10. Receive human quality control.
11. Receive the garment.
12. Use a 7-day fit window and free first alteration.

Designers can:

1. Create a verified profile.
2. Upload a portfolio.
3. Receive matched design requests.
4. Submit bids.
5. Manage orders.
6. Track production.
7. Use Zari Copilot.
8. Manage earnings and capacity.
9. Build their Quality Score.

The most important product loop is:

**Inspiration → Design → Edit → Price → Budget Fit → Designer → Order → QC → Delivery**

The frontend must make this workflow extremely clear.

Every change must have:

# IMPORTANT PRODUCT RULES

1. Never show a fake final price when only an estimate exists.

2. Always distinguish:
   Estimate
   Bid
   Final price

3. Never make price the only marketplace ranking factor.

4. Quality Score must be transparent.

5. Budget Optimizer must always be free.

6. Guest users should experience value before signup.

7. Design edits must preserve visual identity.

8. Every edit creates a new version.

9. Never silently change the user's design.

10. Never silently accept an unmanufacturable instruction.

11. Trust information must be visible at the moment money changes hands.
