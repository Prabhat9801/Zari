# Deploying Zari

Two independent services, deployed separately on Render from one GitHub repo:

| Service | Path | What it is | Needs a database |
|---|---|---|---|
| `zari-api` | [backend/](backend/) | Node 22 + Express 5 + Prisma. Auth, designs, orders, escrow, QC. | Yes — Supabase Postgres |
| `zari-ai-service` | [ai-service/](ai-service/) | Python 3.12 + FastAPI + Claude. Design generation, costing, budget plans. | No — stateless |

The frontend ([artifacts/zari/](artifacts/zari/)) is a static SPA and deploys as a Static Site.

---

## 1. Supabase — create the database

1. https://supabase.com/dashboard → **New project**. Pick the **Mumbai (ap-south-1)** region.
2. Save the database password you set — you cannot read it back later.
3. **Project Settings → Database → Connection string → URI.** Copy **both**:
   - **Transaction pooler** (port `6543`) → this is `DATABASE_URL`. Append `?pgbouncer=true&connection_limit=1`.
   - **Direct connection** (port `5432`) → this is `DIRECT_URL`. Prisma migrations cannot run through the pooler.
4. **Storage → New bucket** → name it `zari-media`, tick **Public bucket**.
5. **Project Settings → API** → copy the **Project URL** and the **`service_role`** key. The service_role key bypasses row-level security — server only, never the browser.

## 2. Create the first migration

Run once from your machine, against the Supabase database:

```bash
cd backend
cp .env.example .env      # fill in DATABASE_URL and DIRECT_URL
npm install
npx prisma migrate dev --name init
npm run seed              # cost rules + demo designers + ops account
```

Commit the generated `backend/prisma/migrations/` folder. **This is required** — in production `docker-entrypoint.sh` runs `prisma migrate deploy`, which only *applies* existing migrations and never creates them.

## 3. Push to GitHub

```bash
git add .
git commit -m "Add Zari backend, AI service, and deployment config"
git push origin main
```

## 4. Deploy on Render

**Render → New → Blueprint → connect this repo → Apply.** [render.yaml](render.yaml) creates both services. Then fill in the secrets Render marked as required:

**On `zari-api`:**

| Variable | Where it comes from |
|---|---|
| `DATABASE_URL`, `DIRECT_URL` | Supabase, step 1 |
| `CORS_ORIGINS` | Your deployed frontend URL(s), comma-separated, no trailing slash |
| `AI_SERVICE_TOKEN` | Invent it: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `AI_SERVICE_URL` | The deployed `zari-ai-service` URL, with `https://` and no trailing slash. Deploy that service first, copy its URL from its Render page, then set this and redeploy the API. |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API |
| `RAZORPAY_*` | Razorpay dashboard (see [backend/.env.example](backend/.env.example)) |

`JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` are generated by Render automatically. `AI_SERVICE_URL` is wired to the AI service by the blueprint.

**On `zari-ai-service`:**

| Variable | Where it comes from |
|---|---|
| `SERVICE_TOKEN` | **The exact same value** as `AI_SERVICE_TOKEN` above |
| `ANTHROPIC_API_KEY` | console.anthropic.com → Settings → API Keys (buy credits first) |

Set `RUN_SEED_ON_START=true` on `zari-api` for the first deploy, then set it back to `false`.

## 5. Razorpay webhook

Once `zari-api` has a URL:

**Razorpay dashboard → Account & Settings → Webhooks → Add New Webhook**
- URL: `https://zari-api-xxxx.onrender.com/api/payments/webhook`
- Events: `payment.captured`, `payment.failed`, `refund.processed`
- Secret: any strong string — paste the same value into `RAZORPAY_WEBHOOK_SECRET`

## 6. Verify

```bash
curl https://zari-api-xxxx.onrender.com/api/health
curl https://zari-api-xxxx.onrender.com/api/health/ready   # checks DB + AI service
curl https://zari-ai-service-xxxx.onrender.com/health
```

`/api/health/ready` returning `{"checks":{"database":true,"aiService":true}}` means both services are wired to each other correctly.

## Local development

```bash
cp backend/.env.example backend/.env          # fill in DB + AI token
cp ai-service/.env.example ai-service/.env    # same AI token + Anthropic key
docker compose up --build
```

API on `http://localhost:8080`, AI service on `http://localhost:9000` (with `/docs` in development). Migrations run automatically on container start.

To run without Supabase, use `docker compose --profile local-db up --build` and point both URLs at `postgresql://zari:zari@postgres:5432/zari`.

---

## Notes and gotchas

- **Migrations run on every container start.** `prisma migrate deploy` is a no-op when the database is current, so it is safe on every deploy and every replica.
- **Render free/starter instances sleep.** A cold start plus a four-concept generation can exceed a browser's patience — the API returns an `AiJob` id immediately and the frontend polls it, which is why the staged loader exists.
- **`AI_SERVICE_TOKEN` and `SERVICE_TOKEN` must match exactly.** A mismatch surfaces as every generation failing with a 502 while `/api/health` still looks fine — check `/api/health/ready`.
- **Anthropic credits.** With no balance, every request fails with a 400 about insufficient funds. Set a spend limit in the Anthropic console before going live.
- **Escrow is a ledger, not a Razorpay feature.** Money is captured to the Zari account and recorded as `HELD`; it becomes `RELEASED` only via the QC pass path. There is deliberately no admin shortcut to pay a designer early.
